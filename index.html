How to use ArchiTrek

The problem
How do these elements connect across layers?

ArchiMate relationships are defined in the spec, but it can be tedious to look up the tables and verify which element types can connect. Even with modeling tools that help you draw links, it’s not always obvious what chain of allowed relationships will get you from one element type to another. ArchiTrek helps you find a valid relationship chain (a “route”) — often crossing Business / Application / Technology layers.

What the app does
Pick points → Find Path → read the explanation
  • Choose 2+ element types using the pickers.
  • Click Find Path to search Appendix B (plus optional derivation rules).
  • Review the diagram and the hop-by-hop explanation; click items to learn more.
How it ranks routes
Strongest Legal Chain (weighted syntax score)

ArchiTrek uses uniform-cost search to rank the Strongest Legal Chain: lower total syntax cost (sum of hop weights), then ties break by fewer hops, then fewer derived hops.

Direct weight 1 Derived weight 5 Association weight 100

These weights can be tuned in Advanced options; higher weight means “avoid this hop unless it’s worth it”.

Selection logic
Ordered vs Connect set
  • Ordered: you decide Start → Via → End; the route must follow that sequence.
  • Connect set: order doesn’t matter; the app reorders points to produce one strongest legal chain that connects everything.
Relationship rules
Direct, + Derived, Semantic rigor
  • Direct: only uppercase Appendix B relationships (strictest).
  • + Derived: also allow §5.7 derivations (lowercase in tables) to unlock more routes.
  • Semantic rigor (Academic / Pragmatic / Discovery): bundles grammar gates with whether §5.2.4 Association may be used as a last-resort bridge. Use Advanced options → Advanced Logic Overrides for manual control.
  • Together: Direct vs +Derived decides which edges exist in the graph; Semantic rigor judges routes and Association on top. They are separate controls.
Context
Story Theme

The Story Theme (top-right) changes scenario labels and narrative wording in explanations (e.g. Abstract vs Hospital vs Death Star). It does not change Direct vs +Derived, Semantic rigor, or other pathfinding rules.

If you get “No path found”
  • Enable + Derived.
  • Choose a looser Semantic rigor (e.g. Discovery) or open Advanced options → Advanced Logic Overrides and allow Association fallback.
  • Add an intermediate element type that sits “between” layers.

Understanding Search Depth: Explicit vs. Inferred

This setting determines which "tier" of the ArchiMate relationship matrix the engine uses.

Direct Mode: The engine only considers Explicit relationships (shown as Uppercase letters in the Appendix B tables). These are the primary, first-degree connections defined as the core building blocks of the language.

+Derived Mode: The engine is allowed to calculate Inferred relationships (shown as Lowercase letters in the Appendix B tables). It uses the Derivation Rules (§5.7) to prove that if A→B and B→C, then a valid logical link exists between A and C across multiple layers.

💡 Why this is different from Semantic Rigor

Think of this as the Source Material. It decides whether we use only the "Direct" (Uppercase) entries or if we are allowed to calculate the "Derived" (Lowercase) entries. Rigor is the Filter—it decides which of those results are architecturally "Strong" based on grammar.

ArchiMate Semantic Rigor Guide

Understanding Semantic Rigor Modes

This engine evaluates architectural paths based on strict ArchiMate 3.1 derivation rules (§5.7). The Rigor Mode determines how strictly the "Grammar" of the language is enforced.

Rigor Mode Core-to-Core Filter V-Shape Filter Association Bridges Purpose
🎓 Academic Strictly Blocked Strictly Blocked Disabled Formal proofs and exam-level modeling accuracy.
🛠️ Pragmatic Strictly Blocked Allowed (Flagged) Enabled (High Penalty) Real-world analysis where data may be fuzzy.
🕵️ Discovery Allowed (Flagged) Allowed (Flagged) Enabled (Low Penalty) "What-if" exploration to find hidden impacts.

Logic Gate Definitions

  • Core-to-Core Filter: Prevents linking two Physical/Technical elements by taking a shortcut through the Motivation layer (e.g., bridging two Servers because they share a "Goal").
  • V-Shape Filter: Prevents "up-then-down" dependency loops (e.g., App A serves Process B, and App C serves Process B). Mathematically they share a process; architecturally they aren't necessarily connected.
  • Association Bridges: Uses the universal §5.2.4 Association to bridge gaps when no formal logical chain exists.

Note: These settings determine the Semantic Strength Badge (Strong, Valid, or Informal) you see in the results.

Strong Valid Informal

💡 Why this is different from Search Depth (Explicit vs. Inferred)

Semantic rigor is the Filter—which routes count as architecturally "Strong" based on grammar and Association rules. Search Depth (the Direct / + Derived toggle) selects the Source Material: only Explicit (Uppercase) Appendix B entries, or also Inferred (Lowercase / §5.7) entries.

You can have a short Explicit hop that is still flagged Informal if it breaks a grammar rule, or a longer Inferred chain that is Strong because it follows the rules.

Semantic rigor

Academic disables §5.2.4 Association bridges; Pragmatic and Discovery allow them as a last resort (penalised in results). Separate from Direct vs +Derived, which controls whether §5.7 derived edges are included in the graph.

Advanced options
Path mode

Connect set is flexible and useful for exploration. Ordered mode is stricter and mainly for intentional Start → … → End chains.

⚠️ Exploratory Mode: The engine will reorder elements to find the most valid syntactic chain. For layered, causality-driven architecture, use Ordered (Start → Via → End) mode.

Path search basics
Algorithm budget
Search effort controls the exploration budget used by the pathfinder.

- Fast: smallest search budget; quickest response, may miss longer alternatives.
- Balanced: default budget; best trade-off for most cases.
- Thorough: largest budget; finds more alternatives, can be slower on dense graphs.

Start with Balanced, then move to Thorough when routes are missing or too repetitive.
Perspective grouping
Advanced Logic Overrides

Override preset defaults here. Changing any option switches the main Semantic rigor control to Custom.

Hop cost tuning
Cost tuning ranks competing legal routes. Lower total cost wins.

- Direct hop cost: baseline for explicit Appendix B links.
- Derived hop cost: cost for §5.7 inferred links (usually above Direct).
- Association hop cost: generic §5.2.4 bridge cost (keep high unless you intentionally want generic links).
- Layer-skip penalty: extra cost when one hop jumps across an intermediate core layer (for example Business → Technology).
- Violation penalty: extra cost for Discovery-mode grammar violations.

Practical defaults: 1 / 5 / 100 / 15 / 50 (Direct / Derived / Association / Layer-skip / Violation).

Search uses weighted UCS: direct/derived/association/layer-skip/violation costs are soft ranking signals, while semantic toggles are hard rules in strict mode and trace tags in discovery mode.

Routes are grouped by share of hops in upper vs infrastructure bands.

- If upper share is at least the threshold, route goes to Business Operations.
- If infrastructure share is at least the threshold, route goes to System Infrastructure.
- Otherwise, route stays in Cross-Layer Alignment.

50% is the most inclusive setting.
